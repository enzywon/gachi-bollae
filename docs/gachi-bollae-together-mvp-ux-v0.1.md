# 같이볼래 — 함께 보기 MVP UX 명세

## 1. 문서 정보

- 문서 버전: v0.1
- 작성일: 2026년 8월 9일
- 대상 제품: 같이볼래 (gachi-bollae)
- 대상 범위: 함께 보기 중심의 1차 MVP 사용자 경험
- 상위 문서: [서비스 디자인 컨셉](./gachi-bollae-service-design-concept-v0.1.md)
- 관련 문서: [시청 기록과 평가 PRD](./gachi-bollae-rating-prd-v0.1.md)

### 1.1 이 문서의 범위

이 문서는 서비스 디자인 컨셉을 실제 화면 흐름과 상태로 옮기기 위한 UX 명세다.
추천 알고리즘의 세부 점수 계산이나 데이터베이스 스키마는 별도 PRD에서 다루고, 여기서는 사용자가 보고 누르고 이해하는 경험을 정의한다.

이번 문서가 정하는 항목은 다음과 같다.

- 함께 보기 MVP의 핵심 사용자 흐름
- 화면별 목적, 입력, 출력, 주요 상태
- 추천 결과 카드에 필요한 정보 구조
- 기록 기능으로 이어지는 사용자 경험
- 1차 구현에서 우선 개선할 항목

### 1.2 현재 구현과의 관계

현재 앱은 다음 흐름을 이미 갖고 있다.

```text
모드 선택 → 시청 상황 → 무드와 취향 → 조건 필터 → 추천 결과 → 기록
```

이 문서는 현재 흐름을 버리지 않고, 실제 출시 기준으로 함께 보기 경험을 더 선명하게 만드는 방향을 제안한다.

---

## 2. UX 목표

### 2.1 핵심 목표

두 사람이 한 기기를 보며 3분 안에 "오늘 이걸 보자"에 도달한다.

### 2.2 보조 목표

- 한 사람의 취향만 반영됐다는 느낌을 줄인다.
- 선택을 방해하는 후보를 초기에 제외한다.
- 추천 이유를 보고 두 사람이 납득할 수 있게 한다.
- 시청 후 기록이 다음 추천의 재료라는 점을 자연스럽게 전달한다.

### 2.3 성공 기준

1차 MVP의 UX 성공 기준은 다음과 같다.

| 기준 | 목표 |
| --- | --- |
| 추천 도달 시간 | 첫 화면에서 결과까지 3분 이내 |
| 추천 결과 수 | 기본 3개 |
| 필수 입력 단계 | 3단계 이내 |
| 함께 보기 입력 | 두 사람의 취향이 분리되어 입력됨 |
| 결과 이해 | 각 추천 카드에 최소 2개 이상의 추천 이유 표시 |
| 기록 연결 | 선택 후 기록 액션이 바로 이어짐 |

---

## 3. 전체 흐름

### 3.1 기본 플로우

```text
1. 첫 화면
2. 함께 보기 시작
3. 지금 상황 선택
4. 오늘 무드와 각자 취향 선택
5. 시간, 형식, OTT, 피하고 싶은 요소 선택
6. 추천 결과 3개 확인
7. 하나 선택 또는 다른 후보 보기
8. 시청 후 기록과 평가 저장
9. 함께 본 목록에서 다시 확인
```

### 3.2 1차 MVP에서의 기본값

- 기본 진입은 함께 보기 모드를 강조한다.
- 혼자 보기 모드는 유지하되 보조 선택지로 둔다.
- 추천 결과는 3개를 기본으로 한다.
- 추천 결과가 없으면 조건을 임의로 완화하지 않는다.
- 기록은 로그인 없이 저장 가능한 구조를 우선한다.

### 3.3 주요 사용자 상태

| 상태 | 설명 | 필요한 UX |
| --- | --- | --- |
| 첫 방문 | 서비스 목적을 아직 모름 | 함께 고르는 서비스임을 즉시 이해 |
| 조건 입력 중 | 두 사람이 한 기기를 번갈아 봄 | 현재 단계와 남은 단계 표시 |
| 결과 검토 중 | 후보를 비교함 | 적은 수의 카드와 명확한 추천 이유 |
| 선택 완료 | 오늘 볼 콘텐츠를 정함 | 기록 또는 새 추천으로 자연스럽게 연결 |
| 재방문 | 과거 기록이 있음 | 함께 본 목록과 추천받기 진입 제공 |

## 4. 화면별 명세

### 4.1 첫 화면

#### 목적

같이볼래가 "함께 볼 콘텐츠를 빠르게 고르는 서비스"라는 점을 첫 화면에서 이해시킨다.

#### 주요 정보

- 서비스명
- 한 줄 가치 제안
- 함께 보기 시작 버튼
- 혼자 보기 보조 버튼
- 대표 상황 예시
- 함께 본 목록 진입

#### 권장 구조

첫 화면의 주 액션은 `함께 볼게요`가 되어야 한다.
`혼자 볼게요`는 유지하되 시각적 우선순위는 낮춘다.

#### 권장 카피

| 요소 | 카피 |
| --- | --- |
| 헤드라인 | 둘이 오늘 볼 콘텐츠를 3분 안에 |
| 보조 문구 | 상황과 각자 취향을 맞춰, 둘 다 납득할 후보만 좁혀드려요. |
| 주 버튼 | 함께 볼게요 |
| 보조 버튼 | 혼자 볼게요 |
| 기록 링크 | 함께 본 목록 |

#### 상태

- 기본 상태: 모드 미선택
- 함께 보기 선택: 상황 선택 단계로 이동
- 혼자 보기 선택: 같은 흐름을 사용하되 파트너 취향 입력 생략

---

### 4.2 상황 선택

#### 목적

지금 보기 적합하지 않은 콘텐츠를 초기에 줄인다.

#### 입력

- 식사 중
- 자기 전
- 집중해서 보기
- 편하게 보기

#### 자동 적용

상황에 따라 피하고 싶은 요소를 기본값으로 제안할 수 있다.
다만 사용자가 언제든 해제할 수 있어야 한다.

| 상황 | 기본 제외 후보 |
| --- | --- |
| 식사 중 | 잔인함·고어, 불쾌한 소재 |
| 자기 전 | 공포·깜짝, 무거운 분위기 |
| 집중해서 보기 | 기본 제외 없음 |
| 편하게 보기 | 기본 제외 없음 |

#### 권장 카피

- 지금은 어떤 시간인가요?
- 상황을 먼저 맞추면 실패할 확률이 줄어요.

#### 다음 버튼 조건

상황을 1개 선택해야 다음 단계로 이동한다.

---

### 4.3 무드와 각자 취향 선택

#### 목적

오늘 원하는 분위기와 두 사람의 장르 선호를 분리해서 받는다.

#### 입력

| 항목 | 선택 방식 | 필수 여부 |
| --- | --- | --- |
| 오늘 무드 | 단일 선택 | 필수 |
| 나의 취향 | 복수 선택 | 1개 이상 필수 |
| 상대 취향 | 복수 선택 | 함께 보기에서 1개 이상 필수 |

#### UX 원칙

- 두 사람의 취향 영역은 같은 무게로 보여준다.
- "상대 취향" 대신 실제 서비스에서는 `같이 보는 사람 취향`처럼 중립적인 표현을 검토한다.
- 취향을 많이 고르는 것이 항상 좋은 결과를 만든다고 느끼게 하지 않는다.
- 선택 개수가 너무 많으면 추천 이유가 흐려질 수 있으므로 1차 MVP에서는 1-3개 선택을 권장한다.

#### 권장 카피

| 요소 | 카피 |
| --- | --- |
| 제목 | 오늘은 어떤 느낌이 좋나요? |
| 나의 취향 | 내가 끌리는 장르 |
| 상대 취향 | 같이 보는 사람이 끌리는 장르 |
| 도움 문구 | 달라도 괜찮아요. 겹치는 지점과 타협 가능한 후보를 같이 볼게요. |

#### 다음 버튼 조건

- 무드가 선택되어야 한다.
- 나의 취향이 1개 이상 선택되어야 한다.
- 함께 보기에서는 상대 취향이 1개 이상 선택되어야 한다.

---

### 4.4 조건 필터

#### 목적

실제로 오늘 볼 수 없는 후보를 제외한다.

#### 입력

| 항목 | 선택 방식 | 기본값 |
| --- | --- | --- |
| 재생 시간 | 단일 선택 | 60분 이내 |
| 콘텐츠 형식 | 단일 선택 | 상관없음 |
| OTT | 단일 선택 | 상관없음 |
| 피하고 싶은 요소 | 복수 선택 | 상황에 따라 기본 제안 |

#### UX 원칙

- 이 단계의 조건은 추천 점수보다 강한 필터로 다룬다.
- `상관없음`은 선택하지 않은 것이 아니라 의도적인 허용 상태로 보여준다.
- 피하고 싶은 요소는 한 명이 선택해도 두 사람 모두에게 적용되는 조건으로 본다.

#### 권장 카피

- 마지막으로 볼 수 있는 조건을 맞춰볼게요.
- 피하고 싶은 요소는 추천에서 제외할게요.

#### 다음 버튼 조건

필수 기본값이 있으므로 별도 선택 없이도 결과로 이동할 수 있다.

---

### 4.5 추천 결과

#### 목적

사용자가 다시 긴 탐색을 하지 않고, 3개 후보 안에서 오늘 볼 콘텐츠를 정한다.

#### 카드 정보 구조

각 추천 카드에는 다음 정보가 필요하다.

| 정보 | 목적 |
| --- | --- |
| 순위 | 후보 비교 |
| 제목 | 콘텐츠 식별 |
| 형식 | 영화, 시리즈, 예능 구분 |
| 재생 시간 | 오늘 볼 수 있는지 판단 |
| OTT | 접근 가능성 판단 |
| 짧은 설명 | 내용 파악 |
| 함께 만족도 또는 적합도 | 우선순위 이해 |
| 추천 이유 | 납득과 대화 촉진 |
| 주요 액션 | 선택, 넘기기, 이미 봤어요 |

#### 추천 이유 규칙

추천 이유는 점수 계산을 그대로 노출하지 않고, 사용자가 이해할 수 있는 짧은 문장으로 보여준다.

최소 2개, 최대 4개의 이유를 표시한다.

추천 이유 후보는 다음과 같다.

- `식사 중에 보기 편해요`
- `오늘 무드와 잘 맞아요`
- `두 사람 모두 고른 코미디 취향이 반영됐어요`
- `한쪽의 추리 취향과 다른 쪽의 드라마 취향을 같이 반영했어요`
- `피하고 싶은 공포 요소가 없어요`
- `60분 안에 볼 수 있어요`

#### 주요 액션

| 액션 | 동작 |
| --- | --- |
| 이걸 볼게요 | 선택 완료 배너 표시 |
| 별로예요 | 현재 후보에 부정 반응 저장 |
| 이미 봤어요 | 기록 또는 평가 진입 제공 |
| 다른 3개 보기 | 같은 조건으로 다른 후보 표시 |
| 조건 수정 | 필터 단계로 이동 |

#### 빈 결과 상태

조건에 맞는 결과가 없을 때는 필수 조건을 자동으로 풀지 않는다.
사용자가 어떤 조건을 완화하면 좋을지 안내한다.

권장 카피:

- 조건에 맞는 콘텐츠가 없어요.
- 피하고 싶은 요소와 필수 조건은 그대로 지켰어요.
- 시간이나 콘텐츠 형식을 조금 넓히면 후보를 찾을 수 있어요.

---

### 4.6 선택 완료

#### 목적

오늘 볼 콘텐츠를 정했다는 상태를 명확히 보여주고, 기록으로 이어질 길을 만든다.

#### 표시 정보

- 선택한 콘텐츠 제목
- 선택 완료 상태
- 기록하기 버튼
- 새로 고르기 버튼

#### 권장 카피

- 이 콘텐츠로 결정했어요.
- 다 보고 나면 별점과 한 줄 감상을 남겨보세요.

#### UX 원칙

선택 완료 후 바로 평가를 강요하지 않는다.
사용자는 지금 콘텐츠를 보러 가야 하므로, 기록은 자연스러운 후속 액션이어야 한다.

---

### 4.7 기록과 평가

#### 목적

함께 본 콘텐츠를 간단히 남기고, 다음 추천에 쓸 데이터를 만든다.

#### 진입점

- 선택 완료 배너의 `다 봤어요, 기록하기`
- 추천 카드의 `이미 봤어요` 후 `평가 남기기`
- 함께 본 목록의 미평가 기록

#### 입력

기록과 평가의 세부 요구사항은 [시청 기록과 평가 PRD](./gachi-bollae-rating-prd-v0.1.md)를 따른다.
UX 관점에서는 1분 안에 저장 가능한 입력량을 유지한다.

#### 권장 구조

- 하단 시트 또는 모달
- 별점
- 시청 상태
- 날짜
- 한 줄 감상
- 저장 버튼

#### UX 원칙

- 별점은 선택 입력으로 둘 수 있다.
- 저장 후 사용자는 추천 결과나 함께 본 목록으로 이동할 수 있어야 한다.
- 기록 저장 성공 메시지는 다음 행동을 함께 제공한다.

---

### 4.8 함께 본 목록

#### 목적

기록을 다시 확인하고, 다음 추천을 받을 이유를 만든다.

#### 표시 정보

- 콘텐츠 제목
- 형식과 OTT
- 시청 날짜
- 시청 상태
- 별점
- 한 줄 감상
- 재시청 여부
- 미평가 안내

#### 주요 액션

- 추천받기
- 기록 수정
- 평가 수정
- 기록 삭제
- 미평가 기록 평가하기

#### UX 원칙

함께 본 목록은 기록 저장의 끝이 아니라 재방문 루프의 시작이어야 한다.
향후에는 목록 상단에 다음 추천으로 이어지는 문구를 둘 수 있다.

권장 카피:

- 지난번에 좋았던 선택을 바탕으로 다시 골라볼까요?

---

## 5. 화면 상태와 예외 처리

### 5.1 진행 상태

추천 입력 단계에서는 현재 단계와 전체 진행률을 보여준다.

```text
1 / 3 상황
2 / 3 취향
3 / 3 조건
```

결과 화면에서는 진행률보다 조건 요약을 우선한다.

### 5.2 뒤로 가기

각 입력 단계에는 이전 버튼이 필요하다.
이전 단계로 돌아가도 기존 선택은 유지한다.

### 5.3 처음부터

추천 흐름 중에는 `처음부터` 액션을 제공한다.
초기화 전 확인 모달은 1차 MVP에서는 생략할 수 있다.

### 5.4 저장 실패

기록 저장 실패 시 사용자가 입력한 값은 유지한다.
오류 문구는 가능한 원인을 알려준다.

예:

- 저장소가 연결되지 않았습니다.
- 기록 테이블이 아직 만들어지지 않았습니다.
- 저장에 실패했습니다. 잠시 후 다시 시도해 주세요.

### 5.5 추천 결과 없음

빈 결과는 실패가 아니라 조건을 지킨 결과로 설명한다.
서비스가 임의로 금지 조건을 풀었다는 인상을 주면 안 된다.

## 6. 카피 가이드

### 6.1 원칙

- 두 사람 중 한쪽을 탓하지 않는다.
- "정답"보다 "오늘 맞는 선택"을 강조한다.
- 과장된 추천 확신을 피한다.
- 사용자가 조건을 바꾸는 일을 실패처럼 느끼게 하지 않는다.
- 기록은 부담보다 다음 선택을 쉽게 만드는 장치로 설명한다.

### 6.2 피해야 할 표현

| 피할 표현 | 이유 |
| --- | --- |
| 완벽한 추천이에요 | 과도한 확신 |
| 상대 취향 때문에 후보가 줄었어요 | 한쪽에게 책임 전가 |
| 조건이 너무 까다로워요 | 사용자 탓 |
| 실패했어요 | 빈 결과를 오류처럼 보이게 함 |

### 6.3 권장 표현

| 상황 | 권장 표현 |
| --- | --- |
| 결과 표시 | 둘 다 무리 없이 볼 만한 후보예요 |
| 빈 결과 | 조건은 지켰고, 후보만 찾지 못했어요 |
| 재추천 | 같은 조건으로 다른 후보를 볼게요 |
| 기록 저장 | 다음에 고를 때 참고할 수 있게 저장했어요 |
| 미평가 안내 | 별점은 나중에 남겨도 괜찮아요 |

## 7. 1차 구현 우선순위

### 7.1 우선순위 A

실제 출시 전 반드시 맞춰야 하는 항목이다.

| 항목 | 설명 |
| --- | --- |
| 함께 보기 중심 첫 화면 | `함께 볼게요`를 주 액션으로 재배치 |
| 추천 이유 개선 | 두 사람 취향 균형과 필터 충족 이유를 더 명확히 표시 |
| 빈 결과 안내 개선 | 어떤 조건을 넓히면 되는지 구체적으로 안내 |
| 선택 완료 후 기록 연결 | 기록하기와 새로 고르기 흐름을 명확히 유지 |

### 7.2 우선순위 B

MVP 품질을 높이는 항목이다.

| 항목 | 설명 |
| --- | --- |
| 취향 선택 개수 안내 | 1-3개 권장 등 입력 부담 완화 |
| 조건 요약 표시 | 결과 화면에서 선택 조건을 읽기 쉽게 표시 |
| 이미 봤어요 안내 개선 | 현재 적용되는 자동 제외 동작을 결과 화면에서 더 명확히 설명 |
| 함께 본 목록 재방문 카피 | 기록에서 추천받기로 이어지는 루프 강화 |

### 7.3 우선순위 C

후속 확장으로 둔다.

| 항목 | 설명 |
| --- | --- |
| 각자 기기 입력 | 페어 코드와 동기화 필요 |
| 개인별 평가 | 프로필 또는 계정 필요 |
| 두 사람별 기록 기반 개인화 | 개인별 프로필과 기록 귀속 정책 필요 |
| 실제 콘텐츠 API | 콘텐츠 식별자, 제공처, 이미지 정책 필요 |

## 8. 현재 구현 대비 차이

| 영역 | 현재 구현 | UX 명세 기준 |
| --- | --- | --- |
| 첫 화면 | 혼자 보기와 함께 보기 모두 노출 | 함께 보기를 주 액션으로 강조 |
| 취향 입력 | 나의 취향, 파트너 취향 | 표현을 더 중립적으로 다듬을 여지 있음 |
| 추천 이유 | 상황, 무드, 취향, 제외 요소 일부 표시 | 두 사람 취향 균형 이유를 더 구체화 |
| 결과 없음 | 조건 완화 안내 | 어떤 조건을 넓힐지 더 구체적으로 안내 |
| 기록 | 선택 후 기록 가능 | 다음 추천의 재료라는 메시지 강화 |
| 함께 본 목록 | 기록과 평가 확인 | 추천으로 돌아오는 재방문 루프 강화 |

## 9. 다음 문서

이 UX 명세 다음에는 현재 프로토타입에 디자인 방향을 입히는 [디자인 적용 계획](./gachi-bollae-design-application-plan-v0.1.md)을 먼저 사용한다.
추천 로직 PRD는 디자인 적용 후, 실제 추천 규칙을 조정해야 할 때 별도로 작성한다.

추천 로직 PRD에서 정해야 할 항목은 다음과 같다.

- 상황, 무드, 취향, 필터의 우선순위
- 두 사람 취향을 합치는 방식
- 한쪽 취향만 맞는 후보의 허용 기준
- 피하고 싶은 요소의 제외 규칙
- 이미 본 콘텐츠 처리
- 추천 이유 생성 규칙
- 결과 다양성 확보 방식
- 빈 결과 fallback 정책

## 10. 미결정 사항

- 첫 화면에서 혼자 보기 모드를 어느 정도까지 드러낼지
- 상대 취향 영역의 최종 명칭
- 취향 선택 개수 제한을 둘지, 권장만 할지
- 추천 결과의 `함께 만족도`를 퍼센트로 유지할지, 문장형 배지로 바꿀지
- 기록 저장 후 추천 결과 화면에 머물지, 함께 본 목록으로 유도할지
