# 같이볼래 — 서비스 디자인 컨셉

## 1. 문서 정보

- 문서 버전: v0.1
- 작성일: 2026년 8월 9일
- 대상 제품: 같이볼래 (gachi-bollae)
- 대상 단계: 실제 서비스 출시를 전제로 한 컨셉 정리
- 우선 사용자: 함께 콘텐츠를 고르는 2인 사용자
- 우선 산출물: 제품 방향, 사용자 경험 원칙, MVP 범위

### 1.1 이 문서의 범위

이 문서는 같이볼래를 실제 서비스로 발전시키기 위한 상위 컨셉 문서다.
추천 로직, UI 개편, 기록 기능, 데이터 연동 같은 후속 작업은 이 문서의 방향을 기준으로 세부 PRD를 작성한다.

이번 문서는 다음을 정한다.

- 누구를 위한 서비스인지
- 어떤 문제를 가장 먼저 해결할지
- 어떤 경험을 제공해야 같이볼래다운지
- 출시 가능한 1차 MVP의 범위는 어디까지인지
- 후속 검증에서 무엇을 확인해야 하는지

### 1.2 이번 단계에서 정한 전제

- 1차 목적은 실제 서비스 출시다.
- 핵심 사용자는 혼자 보는 사람이 아니라 함께 보는 사람이다.
- 1차 산출물은 코드 구현보다 문서화된 서비스 컨셉이다.
- 현재 레포는 추천 흐름과 기록 기능을 검증하는 프로토타입 단계다.

## 2. 배경과 문제 정의

### 2.1 현재 제품 상태

같이볼래는 상황과 취향을 입력하면 영화, 시리즈, 예능 중 3개의 추천 결과를 보여준다.
현재 흐름은 다음 요소를 갖고 있다.

- 혼자 보기와 함께 보기 모드
- 식사 중, 자기 전, 집중해서 보기, 편하게 보기 같은 시청 상황
- 현재 원하는 무드와 장르 취향
- 두 사람의 취향 입력
- 재생 시간, 콘텐츠 형식, OTT 필터
- 피하고 싶은 분위기와 소재 제외
- 추천 결과 선택, 넘기기, 시청 완료 기록
- 함께 본 목록과 별점, 한 줄 감상 저장

현재 데이터는 데모 콘텐츠이며 실제 OTT 카탈로그와 사용자 계정은 아직 연결되지 않았다.

### 2.2 핵심 문제

함께 콘텐츠를 볼 때 사람들은 "무엇을 볼지"보다 "어떻게 합의할지"에서 더 자주 지친다.

대표적인 문제는 다음과 같다.

- 각자 보고 싶은 장르나 분위기가 다르다.
- 한 사람은 가볍게 보고 싶고, 다른 사람은 몰입하고 싶다.
- 식사 중, 자기 전, 짧은 여유 시간처럼 상황에 맞지 않는 콘텐츠를 고르면 실패감이 크다.
- OTT 앱을 옮겨 다니다가 고르는 시간이 길어진다.
- 둘 다 괜찮다고 느끼는 선택지를 찾기 전에 피로해진다.
- 이전에 같이 본 콘텐츠와 반응이 다음 선택에 잘 반영되지 않는다.

### 2.3 문제 정의문

같이볼래는 함께 콘텐츠를 보는 두 사람이 상황과 취향 차이 때문에 선택을 미루거나 포기하지 않도록, 짧은 질문으로 합의 가능한 후보를 좁혀 주는 서비스다.

## 3. 제품 컨셉

### 3.1 한 줄 정의

둘이 오늘 보기 좋은 콘텐츠를 3분 안에 합의하도록 돕는 상황 기반 추천 서비스.

### 3.2 핵심 가치 제안

같이볼래는 추천을 "정답 맞히기"가 아니라 "둘이 납득할 선택지를 빠르게 찾는 과정"으로 설계한다.

사용자는 다음 가치를 얻어야 한다.

- 지금 상황에 맞지 않는 후보를 먼저 덜어낸다.
- 두 사람의 취향을 따로 입력하고 균형 있게 반영한다.
- 왜 이 콘텐츠가 나왔는지 이해할 수 있다.
- 고른 뒤의 기록과 평가가 다음 추천의 근거로 쌓인다.

### 3.3 서비스 성격

같이볼래는 귀엽기만 한 추천 앱보다 조금 더 실용적이어야 한다.
동시에 차갑고 분석적인 큐레이션 도구처럼 느껴져서는 안 된다.

서비스 톤은 다음에 가깝다.

- 빠르게 고르게 해 주는 진행자
- 두 사람의 취향을 공평하게 듣는 중재자
- 상황에 맞지 않는 선택을 조용히 걸러 주는 도우미
- 기록을 통해 다음 선택을 더 쉽게 만드는 개인화 서비스

### 3.4 차별점

일반적인 콘텐츠 추천 서비스는 개인 취향이나 인기 순위를 중심으로 추천한다.
같이볼래는 다음 차이를 가져야 한다.

| 구분 | 일반 추천 | 같이볼래 |
| --- | --- | --- |
| 기준 | 개인 취향, 인기, 시청 이력 | 두 사람의 취향, 현재 상황, 피하고 싶은 요소 |
| 목표 | 볼 만한 콘텐츠 탐색 | 함께 볼 콘텐츠 합의 |
| 흐름 | 추천 목록을 탐색 | 짧은 질문 후 후보 압축 |
| 결과 | 많이 보여주기 | 납득 가능한 소수 후보 제시 |
| 데이터 | 개인 시청 이력 | 함께 본 기록과 두 사람의 반응 |

## 4. 핵심 사용자

### 4.1 1차 사용자

같이 콘텐츠를 보려는 2인 사용자.

예시는 다음과 같다.

- 커플이나 부부
- 친구나 룸메이트
- 가족 구성원 2명
- 자주 함께 콘텐츠를 보는 고정 페어

### 4.2 대표 상황

1차 출시에서는 다음 상황을 우선한다.

- 저녁 식사 중 가볍게 볼 콘텐츠를 고를 때
- 자기 전에 부담 없는 한 편을 고를 때
- 주말에 둘 다 만족할 영화나 시리즈를 고를 때
- 한쪽 취향에만 치우치지 않는 선택지를 찾고 싶을 때

### 4.3 사용자 니즈

사용자는 더 많은 후보를 보고 싶은 것이 아니라, 실패 가능성이 낮은 후보를 빨리 얻고 싶어 한다.

중요 니즈는 다음 순서로 본다.

1. 지금 보기 불편한 콘텐츠를 피한다.
2. 둘 다 최소한 괜찮은 선택지를 찾는다.
3. 고르는 시간을 줄인다.
4. 추천 이유를 보고 납득한다.
5. 같이 본 기록이 다음 추천에 반영된다.

## 5. 경험 원칙

### 5.1 선택 피로를 줄인다

질문은 많아질수록 추천 정확도가 올라갈 수 있지만, 사용자가 지치면 서비스 목적이 깨진다.
1차 경험은 3분 안에 추천 결과에 도달해야 한다.

### 5.2 둘의 입력을 분리해서 받는다

함께 보기 모드에서는 "우리 취향"을 한 번에 묻기보다 각자의 선호를 분리해서 받는다.
그래야 한 사람의 취향이 묻히지 않고, 추천 이유에서도 균형을 설명할 수 있다.

### 5.3 상황을 취향보다 먼저 본다

식사 중, 자기 전, 집중해서 보기 같은 상황은 추천 실패를 크게 좌우한다.
따라서 상황에 맞지 않는 콘텐츠는 취향 점수가 높아도 우선순위를 낮추거나 제외한다.

### 5.4 피하고 싶은 요소는 강한 조건으로 다룬다

잔인함, 공포, 불쾌한 소재처럼 사용자가 명시적으로 피한 요소는 추천 점수보다 강하게 반영한다.
함께 보는 경험에서는 한 명이 불편하면 추천이 실패한 것으로 본다.

### 5.5 결과는 적게, 이유는 분명하게 보여준다

추천 결과는 많을수록 선택을 다시 사용자에게 떠넘긴다.
1차 MVP에서는 3개 내외의 후보를 유지하되, 각 후보가 왜 나왔는지 짧게 설명한다.

### 5.6 기록은 다음 선택을 위한 재료다

함께 본 목록은 단순한 시청 일지가 아니라 다음 추천을 개선하는 입력이어야 한다.
별점, 한 줄 감상, 시청 상황, 함께 보기 모드는 이후 개인화의 핵심 데이터가 된다.

## 6. 핵심 사용자 여정

### 6.1 첫 방문

사용자는 같이볼래에 들어와 혼자 볼지 함께 볼지 선택한다.
1차 서비스에서는 함께 보기 모드를 기본 추천 흐름으로 강조한다.

목표는 사용자가 서비스의 핵심이 "함께 고르기"임을 첫 화면에서 바로 이해하는 것이다.

### 6.2 조건 입력

사용자는 현재 상황, 원하는 무드, 각자의 취향, 재생 시간과 OTT 같은 조건을 입력한다.

이 단계의 목표는 정확한 프로필 작성이 아니라 오늘의 선택에 필요한 최소 정보를 얻는 것이다.

### 6.3 추천 결과 확인

서비스는 3개 내외의 추천 후보를 보여준다.
각 후보에는 다음 정보가 필요하다.

- 제목
- 형식과 재생 시간
- 제공 OTT
- 짧은 설명
- 두 사람의 취향과 맞는 이유
- 피하고 싶은 요소를 피했다는 안심 정보

### 6.4 선택과 기록

사용자는 후보 중 하나를 고르거나 넘긴다.
시청 후에는 별점과 한 줄 감상을 남길 수 있다.

기록은 다음 추천에서 "이미 봤는지", "둘이 만족했는지", "어떤 상황에서 좋았는지"를 판단하는 근거가 된다.

### 6.5 재방문

재방문 사용자는 이전에 함께 본 기록을 바탕으로 더 빠르게 추천을 받을 수 있어야 한다.
장기적으로는 "우리 둘에게 잘 맞는 분위기"를 보여주는 방향으로 확장한다.

## 7. 1차 MVP 범위

### 7.1 포함

- 함께 보기 중심의 추천 흐름
- 각자 취향 입력
- 시청 상황과 무드 선택
- 재생 시간, 형식, OTT 필터
- 피하고 싶은 요소 제외
- 추천 결과 3개 제시
- 추천 이유 요약
- 선택, 넘기기, 이미 봤어요 액션
- 시청 기록 저장
- 별점과 한 줄 감상
- 함께 본 목록
- 데이터베이스 기반 기록 저장

### 7.2 제외

| 제외 항목 | 제외 이유 |
| --- | --- |
| 사용자 계정 | 1차 출시에서는 진입 장벽이 크다. 익명 소유자 키 또는 단순 페어 코드로 시작한다 |
| 각자 기기에서 입력 | 동기화와 인증 복잡도가 높다. 1차는 한 기기에서 함께 입력한다 |
| 실제 OTT 재생 연동 | 권한과 제휴 범위가 크다. 우선 제공처 표시까지만 검증한다 |
| 대규모 카탈로그 탐색 | 추천 합의 경험 검증이 먼저다 |
| 소셜 공유 | 핵심 문제 해결 이후 확장한다 |
| 통계 대시보드 | 충분한 기록 데이터가 쌓인 뒤 의미가 있다 |

### 7.3 출시 후보 확장

1차 MVP가 검증되면 다음 순서로 확장한다.

1. 실제 콘텐츠 카탈로그 연동
2. 페어 프로필 또는 초대 코드
3. 각자 기기에서 취향 입력
4. 함께 본 기록 기반 추천 가중치
5. 상황별 만족도 분석
6. 이미 본 콘텐츠 자동 제외

## 8. 추천 설계 방향

### 8.1 추천의 목표

추천 알고리즘의 1차 목표는 한 사람에게 가장 잘 맞는 콘텐츠를 찾는 것이 아니다.
두 사람이 오늘 상황에서 받아들일 수 있는 후보를 찾는 것이다.

### 8.2 우선순위

추천 조건은 다음 우선순위로 반영한다.

1. 피하고 싶은 요소
2. 시청 상황
3. 재생 시간과 형식, 제공 OTT
4. 두 사람의 취향 교집합
5. 각자 취향의 균형
6. 현재 원하는 무드
7. 과거 기록과 평가

### 8.3 결과 설명

추천 이유는 기술적인 점수 설명보다 사용자의 판단을 돕는 문장이어야 한다.

예시는 다음과 같다.

- 식사 중 보기 편하고, 두 사람 모두 고른 코미디 취향이 맞아요.
- 자기 전에 부담 없는 30분대 시리즈라 오늘 상황에 잘 맞아요.
- 한 사람의 추리 취향과 다른 사람의 드라마 취향이 같이 반영됐어요.
- 피하고 싶은 공포 요소가 없는 후보만 골랐어요.

## 9. UX와 톤앤매너

### 9.1 UX 방향

같이볼래의 화면은 탐색형 콘텐츠 서비스보다 결정 보조 도구에 가깝게 설계한다.

중요한 화면 특성은 다음과 같다.

- 첫 화면에서 함께 보기 목적이 분명해야 한다.
- 질문 단계는 짧고 현재 단계가 보여야 한다.
- 선택지는 눌러 보기 쉬운 칩과 버튼 중심으로 구성한다.
- 추천 결과는 카드 수를 제한하고 비교가 쉬워야 한다.
- 기록하기는 추천 흐름에서 자연스럽게 이어져야 한다.

### 9.2 카피 원칙

- 명령형보다 제안형을 사용한다.
- 추천을 과장하지 않는다.
- 사용자가 선택 실패를 했다고 느끼게 하지 않는다.
- 두 사람 중 한쪽을 기준으로 몰아가지 않는다.

예시는 다음과 같다.

| 상황 | 권장 카피 |
| --- | --- |
| 모드 선택 | 오늘은 누구와 볼까요? |
| 상황 선택 | 지금 보기 좋은 조건부터 맞춰볼게요 |
| 취향 입력 | 각자 끌리는 장르를 골라주세요 |
| 결과 | 둘 다 무리 없이 볼 만한 후보예요 |
| 재추천 | 조건은 유지하고 다른 후보를 볼게요 |

### 9.3 시각적 방향

시각 톤은 가볍고 친근하되, 실제 선택 도구로 신뢰할 수 있어야 한다.

- 과도한 장식보다 선택 흐름을 우선한다.
- 모바일에서 한 손으로 조작 가능한 크기를 유지한다.
- 콘텐츠 포스터 또는 포스터를 대체할 수 있는 시각 요소를 적극 사용한다.
- 색상은 따뜻한 포인트를 허용하되, 추천 결과의 가독성을 해치지 않는다.
- 귀여운 표현은 보조 요소로 쓰고 핵심 액션은 명확하게 둔다.

## 10. 검증 계획

### 10.1 검증 질문

1차 출시 전에는 다음 질문을 검증한다.

- 사용자가 3분 안에 추천 결과에 도달하는가?
- 함께 보기 모드의 가치가 첫 화면에서 이해되는가?
- 두 사람의 취향 입력이 번거롭지 않은가?
- 추천 결과 3개가 충분한가?
- 추천 이유가 선택에 도움이 되는가?
- 기록 기능이 다음에 다시 쓸 이유를 만드는가?

### 10.2 관찰 지표

출시 후에는 다음 지표를 우선 본다.

- 첫 화면에서 추천 결과까지의 완료율
- 추천 결과까지 걸린 시간
- 추천 후보 선택률
- 다시 추천 요청률
- 기록 저장률
- 별점 입력률
- 재방문율

### 10.3 정성 피드백

사용자 인터뷰에서는 다음 질문을 우선한다.

- 둘이 고를 때 실제로 덜 피곤했나요?
- 추천 결과가 둘 다 납득할 만했나요?
- 입력 질문 중 불필요하거나 어려운 것이 있었나요?
- 추천 이유가 선택에 영향을 줬나요?
- 다음에도 같이볼래를 열 이유가 있나요?

## 12. 현재 결정 사항

- 같이볼래의 1차 서비스 방향은 함께 보는 사람을 위한 합의형 추천이다.
- 1차 출시에서는 한 기기에서 함께 입력하는 흐름을 우선한다.
- 추천 결과는 많은 탐색보다 3개 내외의 후보 압축을 우선한다.
- 피하고 싶은 요소와 시청 상황은 취향보다 강하게 반영한다.
- 시청 기록과 평가는 다음 추천 개선을 위한 핵심 데이터로 본다.

## 13. 미결정 사항

- 1차 출시에서 실제 콘텐츠 API를 연동할지, curated 데이터로 시작할지
- 익명 소유자 키를 유지할지, 페어 코드 개념을 도입할지
- 각자 취향 입력을 같은 화면에서 받을지, 순차 단계로 받을지
- 추천 결과 설명을 고정 문장 템플릿으로 둘지, 규칙 기반으로 생성할지
- 함께 본 기록을 언제부터 추천 점수에 반영할지
