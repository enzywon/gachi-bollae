# 코드 리뷰 가이드

코드 리뷰의 목적은 취향을 통일하는 것이 아니라 오류와 위험을 병합 전에 찾고, 변경 의도를 함께 이해하는 것입니다.

## 리뷰 순서

1. PR의 변경 이유와 범위를 읽습니다.
2. CI가 통과했는지 확인합니다.
3. 사용자 동작, 데이터 흐름, 인증과 보안을 먼저 봅니다.
4. 테스트가 중요한 실패 경로를 다루는지 확인합니다.
5. 마지막으로 이름, 구조, 중복과 가독성을 봅니다.

## 코멘트 수준

코멘트 앞에 다음 표식을 붙이면 의도가 분명해집니다.

- **blocker:** 병합 전에 반드시 해결해야 하는 오류, 보안 문제, 데이터 손실 위험
- **important:** 회귀 가능성이나 유지보수 문제처럼 해결을 강하게 권장하는 항목
- **suggestion:** 더 나은 대안이지만 작성자가 선택할 수 있는 개선안
- **question:** 의도나 전제 조건을 확인하는 질문
- **praise:** 유지하면 좋은 설계나 구현

## 좋은 리뷰 코멘트

- 한 코멘트에는 한 가지 문제만 다룹니다.
- 문제가 발생하는 조건과 사용자 영향을 함께 적습니다.
- 가능하면 수정 방향이나 GitHub suggestion을 제시합니다.
- 근거 없이 개인 취향만 강제하지 않습니다.
- 범위 밖의 개선은 현재 PR을 막는 대신 후속 이슈로 분리합니다.

```text
blocker: 인증되지 않은 요청에서도 이 분기가 실행되어 다른 사용자의 기록을 읽을 수 있습니다.
서버에서 사용자 ID를 먼저 확인하고, 조회 조건에도 해당 ID를 포함해 주세요.
```

## 혼자 개발할 때

PR 작성자가 자신의 PR을 승인할 수는 없으므로 승인 1개를 필수 조건으로 두지 않습니다. 대신 아래 항목을 병합 조건으로 사용합니다.

- `PR title`과 `Quality` CI 통과
- 모든 리뷰 대화 해결
- draft 해제 전 `Review focus` 작성
- 중요한 변경은 PR 링크와 함께 별도 코드 리뷰 요청

AI 리뷰를 요청할 때는 “전체적으로 봐줘”보다 다음처럼 범위를 명확히 지정하는 편이 좋습니다.

```text
이 PR에서 correctness, 보안, 회귀 가능성을 우선 검토하고
실제 수정이 필요한 내용만 파일과 줄 번호를 붙여 코멘트해 줘.
```

## 자동 AI 리뷰

Ready 상태의 PR을 열면 다음 리뷰가 자동으로 실행됩니다.

- CodeRabbit: 저장소에 연결된 모든 Ready PR 리뷰
- Codex: `enzy-o0` 또는 `kjw2000e`가 작성한 Ready PR에 `enzy-won` 계정으로 리뷰 요청

Draft PR에서는 자동 리뷰를 요청하지 않습니다. Codex는 PR을 처음 Ready 상태로 만들 때 한 번만 요청하며, 새 커밋마다 다시 실행하지 않습니다. 변경 후 재검토가 필요하면 `enzy-won` 계정으로 `@codex review`를 직접 남깁니다.

Codex 자동 요청을 사용하려면 저장소 관리자가 다음 설정을 한 번 완료해야 합니다.

1. `enzy-won` 계정에서 Fine-grained personal access token을 만듭니다.
2. Resource owner는 `enzywon` 조직, 접근 저장소는 `gachi-bollae` 하나만 선택합니다.
3. Repository permissions에서 `Issues: Read and write`만 추가합니다. GitHub는 PR의 일반 댓글을 Issue comment로 처리합니다.
4. 저장소의 `Settings > Secrets and variables > Actions`에 `ENZY_WON_CODEX_REVIEW_TOKEN` 이름으로 저장합니다.

토큰은 파일이나 PR에 입력하지 않습니다. 만료일을 설정하고, 만료되거나 폐기한 뒤에는 같은 이름의 Secret만 교체합니다. 자동화는 Secret에 접근하는 대신 PR 브랜치를 체크아웃하거나 실행하지 않도록 제한되어 있습니다.

협업자가 생기면 `.github/CODEOWNERS`를 추가하고 영역별 담당자에게 리뷰가 자동 요청되도록 확장합니다.
