# 같이볼래 — 시청 기록과 평가 PRD

## 1. 문서 정보

- 문서 버전: v0.1
- 작성일: 2026년 8월 4일
- 대상 제품: 같이볼래 (gachi-bollae)
- 대상 기능: 시청 기록 등록과 콘텐츠 평가
- 참고 문서: Enzywon PICK PRD v0.4 (이전 프로젝트 문서, 저장소 외부에서 관리)
- 개발 단계: 1단계 MVP

### 1.1 이 문서의 범위

같이볼래는 지금 "무엇을 볼지 고르는" 추천 흐름만 가진 프로토타입이다.
이 문서는 고른 다음의 흐름, 즉 **본 것을 기록하고 평가하고 다시 꺼내 보는 기능**을 정의한다.

### 1.2 참고 문서와의 관계

Enzywon PICK PRD v0.4는 부부·커플 2인이 각자 기기에서 블라인드로 평가하는 제품을 정의한다.
같이볼래는 현재 계정과 프로필 개념이 없고 단일 기기에서 동작하는 프로토타입이므로,
평가 규칙은 이식하되 **2인 블라인드 구조는 이번 범위에서 제외**한다.
다만 이후 블라인드를 도입할 때 스키마를 다시 설계하지 않도록 승격 경로를 함께 정의한다(9장).

## 2. 배경과 문제 정의

### 2.1 현재 제품 상태

- 추천 흐름: 모드 선택 → 시청 상황 → 무드와 취향 → 조건 필터 → 추천 결과 3개
- 추천 결과 카드의 액션: `이걸 볼게요`, `별로예요`, `이미 봤어요`
- 콘텐츠는 데모 데이터 6건이며 외부 API를 연동하지 않았다.
- 저장소가 없다. 새로고침하면 모든 선택이 사라진다.

### 2.2 해결하려는 문제

- 추천을 받아 콘텐츠를 골라도 무엇을 봤는지 남지 않는다.
- 본 다음의 감상을 남길 곳이 없어 추천 경험이 한 번 쓰고 끝난다.
- 이미 본 콘텐츠가 다시 추천된다.
- 어떤 상황과 무드에서 고른 선택이 좋았는지 되짚을 근거가 없다.

### 2.3 이 기능이 만드는 가치

- 추천 → 시청 → 평가 → 재추천으로 이어지는 흐름을 닫는다.
- 평가 데이터는 이후 추천 품질 개선의 입력이 된다.
- 추천 당시의 상황과 무드를 함께 남겨 "이 상황에서 고른 선택이 맞았는지" 확인할 수 있다.

## 3. 제품 원칙

### 3.1 기록은 추천의 연장선에 있다

기록을 위한 별도 진입점을 먼저 만들지 않는다.
추천 결과 카드에서 자연스럽게 이어지도록 한다.

### 3.2 기록은 1분 안에 끝난다

필수 입력은 별점 하나다. 나머지는 모두 기본값을 제공한다.

### 3.3 되돌릴 수 있어야 한다

잘못 입력한 상태, 날짜, 평가는 삭제하지 않고 고칠 수 있다.
되돌릴 수 없는 입력은 사용자를 신중하게 만드는 대신 기록을 미루게 만든다.

### 3.4 모바일을 우선한다

평가 입력은 하단 시트로 제공하고 주요 버튼은 한 손 엄지 범위에 배치한다.

### 3.5 콘텐츠 정보는 기록 시점의 값을 남긴다

콘텐츠 데이터는 아직 코드 안의 데모 배열이고 앞으로 외부 API로 바뀐다.
기록은 참조만 저장하지 않고 제목과 형식 같은 값을 함께 남겨, 원본이 바뀌어도 과거 기록이 깨지지 않게 한다.

## 4. 사용자와 시나리오

### 4.1 사용자

혼자 또는 둘이 함께 콘텐츠를 보고, 본 것을 가볍게 남기고 싶은 사람.
현재는 한 대의 기기를 사용하는 단일 사용자로 가정한다.

### 4.2 핵심 시나리오

#### 시나리오 1: 추천받은 콘텐츠를 보고 기록

추천 결과에서 `이걸 볼게요`를 누르고 콘텐츠를 본다.
다시 앱에 들어와 `다 봤어요, 기록하기`를 눌러 별점과 한 줄 감상을 남긴다.

#### 시나리오 2: 이미 본 콘텐츠 평가

추천 결과에 이미 본 콘텐츠가 나온다.
`이미 봤어요`를 눌러 추천에서 제외하면서, 원하면 그 자리에서 평가를 남긴다.

#### 시나리오 3: 나중에 평가

바로 평가하지 않고 기록만 남긴다.
나중에 목록 상단의 미평가 안내에서 해당 기록을 골라 별점을 남긴다.

#### 시나리오 4: 기록 되돌아보기

`함께 본 목록`에서 최근 시청순 또는 별점 높은 순으로 확인한다.
같은 콘텐츠를 여러 번 봤다면 하나의 카드로 묶여 재시청 횟수가 표시된다.

## 5. 기능 범위

### 5.1 1단계 MVP 포함

- 시청 기록 등록 (상태, 날짜, 시즌, 메모)
- 별점 평가 (1~5점 정수)
- 한 줄 감상 (최대 200자, 선택)
- 평가 수정과 수정 이력 표시
- 미평가 기록 안내
- 함께 본 목록 (작품 단위 묶음, 재시청 배지)
- 정렬 2종, 필터 2종
- 기록 상세 조회
- 기록 수정과 삭제
- 추천 맥락(상황·무드·모드) 스냅샷 저장
- D1 영속화

### 5.2 이번 범위에서 제외

| 제외 항목 | 사유 |
| --- | --- |
| 2인 블라인드 평가 | 계정과 프로필 구분 수단이 없다. 9장에 승격 경로만 정의한다 |
| 프로필 A/B 전환 | 위와 동일 |
| 평균 별점과 별점 차이 | 평가자가 1인이라 성립하지 않는다 |
| 로그인과 계정 | 프로토타입 단계. 쿠키 기반 소유자 키로 대체한다 |
| 찜 목록과 찜 자동 제거 | 현재 제품에 찜 개념이 없다 |
| TMDB 연동과 OTT 제공처 캐시 | 데모 데이터를 유지한다. `contentKey`로 전환에 대비한다 |
| 선택형 평가 태그 | 2단계 |
| 별점 0.5점 단위 | 2단계 |
| 통계 화면 | 2단계 |
| 평가 데이터를 반영한 추천 | 3단계 |

### 5.3 2단계 후보

- 평가 이력을 반영한 추천 가중치
- 이미 본 콘텐츠 추천 제외 자동 반영
- 선택형 평가 태그
- 상황·무드별 만족도 통계
- 콘텐츠 검색으로 직접 기록 추가

## 7. 기능 요구사항

### 7.1 시청 기록 등록

#### 진입점

| 진입점 | 동작 |
| --- | --- |
| 추천 결과 카드의 `이걸 볼게요` | 선택 배너에 `다 봤어요, 기록하기` 버튼을 노출한다 |
| 추천 결과 카드의 `이미 봤어요` | 카드에 `평가 남기기` 버튼을 노출한다 |
| 함께 본 목록의 미평가 안내 | 해당 기록의 평가 입력으로 바로 이동한다 |

#### 입력 항목

| 항목 | 필수 | 기본값 |
| --- | --- | --- |
| 시청 상태 | 필수 | `다 봤어요` |
| 종료일 | 상태에 따라 필수 | 오늘 (KST) |
| 시작일 | 상태에 따라 필수 | 없음 |
| 시즌 | 시리즈·예능일 때 선택 | 없음 |
| 메모 | 선택 | 없음 |
| 별점 | 선택 (미입력 시 미평가 기록) | 없음 |
| 한 줄 감상 | 선택 | 없음 |

#### 시청 상태

- `보는 중` (`watching`)
- `다 봤어요` (`completed`)
- `중단했어요` (`dropped`)

#### 날짜 정책

- `보는 중`은 시작일이 필요하다.
- `다 봤어요`와 `중단했어요`는 종료일이 필요하다.
- 기본 날짜는 오늘이며, 현재 시각이 KST 기준 오전 4시 이전이면 전날을 사용한다.
- 과거 날짜는 선택할 수 있고 미래 날짜는 입력할 수 없다.
- 종료일은 시작일보다 빠를 수 없다.
- 날짜는 KST 기준 `YYYY-MM-DD` 문자열로 저장한다.

#### 콘텐츠 형식별 기록 단위

- `영화`는 작품 단위로 기록한다. `seasonNumber`는 저장하지 않는다.
- `시리즈`와 `예능`은 시즌 단위 기록을 허용한다. `seasonNumber`는 선택 입력이다.
- 같은 콘텐츠와 시즌에 대해 복수 기록을 허용한다. 재시청은 새 기록으로 남긴다.

#### 추천 맥락 스냅샷

기록 생성 시 추천 흐름의 값을 함께 저장한다.

- `watchMode`: `solo` 또는 `together`
- `pickedContext`: 식사 중, 자기 전 등
- `pickedMood`: 오늘 원했던 무드

추천 흐름을 거치지 않고 만든 기록은 이 값들이 비어 있을 수 있다.

필수

### 7.2 평가

#### 평가 항목

- 별점: 1점부터 5점까지 정수
- 한 줄 감상: 최대 200자, 선택

#### 제출 규칙

- 별점을 입력하면 평가가 생성된다. 별점 없이 감상만 남길 수 없다.
- 임시 저장은 없다. 저장 버튼을 누르면 제출 완료로 처리한다.
- 별점 없이 기록만 저장할 수 있으며, 이 기록은 미평가 상태로 남는다.
- `보는 중` 상태의 기록은 미평가 안내에 표시하지 않는다.

#### 우선순위

필수

---

### 7.3 평가 수정

- 평가는 횟수 제한 없이 수정할 수 있다.
- 실제 값이 바뀐 저장에만 `editCount`를 1 증가시키고 `editedAt`을 갱신한다.
- 값이 기존과 동일하면 수정으로 기록하지 않는다.
- 수정된 평가에는 `수정됨`을 표시하고, 2회 이상이면 `n회 수정됨`으로 표시한다.
- 수정 시 별도의 확인 창을 표시하지 않는다.
- 평가만 개별 삭제하는 기능은 제공하지 않는다.

#### 우선순위

필수

---

### 7.4 미평가 안내

- 별점이 없는 기록의 개수를 함께 본 목록 상단에 표시한다.
- `다 봤어요` 또는 `중단했어요` 상태의 기록만 대상으로 한다.
- 최근 종료일순으로 정렬한다.
- 안내에서 평가 입력으로 바로 이동할 수 있다.

#### 우선순위

필수

---

### 7.5 함께 본 목록

#### 표시 정보

- 콘텐츠 제목과 형식
- 대표 시청 날짜
- 대표 시청 상태
- 시즌
- 별점
- 한 줄 감상 요약
- 재시청 횟수
- 추천 맥락 (상황·무드)

#### 기록 묶음 정책

- 같은 `contentKey`의 기록이 여러 개면 하나의 카드로 묶는다.
- 대표 기록은 가장 최근에 시청한 기록이다. 날짜가 같으면 나중에 생성된 기록을 대표로 한다.
- 대표 날짜, 대표 상태, 대표 시즌, 대표 별점은 모두 대표 기록의 값을 사용한다.
- 기록이 2개 이상이면 재시청 배지를 표시한다.
- 카드를 선택하면 해당 콘텐츠의 전체 기록을 확인할 수 있다.

#### 정렬

| 정렬 | 규칙 |
| --- | --- |
| 최근 시청순 | 대표 기록의 기준일 내림차순 |
| 별점 높은 순 | 대표 기록의 별점 내림차순. 동점은 최근 시청순. 별점이 없는 카드는 하단에 최근 시청순으로 배치 |

기준일은 종료일이 있으면 종료일, 없으면 시작일이다.

#### 필터

- 콘텐츠 형식: 전체 / 영화 / 시리즈 / 예능
- 시청 상태: 전체 / 보는 중 / 다 봤어요 / 중단했어요

시청 상태 필터는 대표 기록의 상태를 기준으로 판정한다.

#### 우선순위

필수

### 7.6 기록 상세

- 해당 콘텐츠의 전체 시청 기록을 최근순으로 표시한다.
- 각 기록의 상태, 날짜, 시즌, 메모, 별점, 한 줄 감상을 표시한다.
- 각 기록에서 평가를 수정할 수 있다.
- 각 기록의 상태와 날짜를 수정할 수 있다.
- 기록을 삭제할 수 있다.

#### 삭제 정책

- 삭제 전 확인 창을 표시하고, 평가도 함께 삭제된다는 사실을 명시한다.
- 삭제된 기록은 복구하지 않는다.
- 상태를 잘못 입력한 경우 삭제 대신 상태 변경을 안내한다.

#### 우선순위

필수

### 7.7 시청 상태 전이

세 상태 간 모든 방향의 변경을 허용한다.

```text
보는 중  ↔ 다 봤어요
보는 중  ↔ 중단했어요
중단했어요 ↔ 다 봤어요
```

- 상태를 변경해도 이미 제출된 평가는 유지한다.
- `보는 중`으로 되돌리면 미평가 안내에서 사라지지만 평가는 보존한다.
- 다시 `다 봤어요`로 변경하면 기존 평가가 그대로 표시된다.
- 상태 변경 시 새 상태에 필요한 날짜가 비어 있으면 입력을 요청한다.

## 9. 데이터 구조

총 2개 테이블을 사용한다. 저장소는 Cloudflare D1(SQLite)이며 Drizzle ORM으로 접근한다.

### 9.1 watch_records

```text
id
owner_key
content_key
content_title
content_format
content_provider
content_runtime
poster_palette
watch_mode
watch_status
started_on
finished_on
season_number
memo
picked_context
picked_mood
created_at
updated_at
```

- `owner_key`는 쿠키로 발급한 익명 소유자 식별자다. 이후 그룹 식별자로 승격한다.
- `content_key`는 `demo:5` 형태이며, 외부 API 도입 시 `tmdb:movie:12345` 형태로 확장한다.
- `content_title`부터 `poster_palette`까지는 기록 시점의 스냅샷이다. 원본 콘텐츠 데이터가 바뀌어도 과거 기록이 깨지지 않게 한다.
- `watch_mode`는 `solo` 또는 `together`다.
- `watch_status`는 `watching`, `completed`, `dropped` 3종이다.
- `season_number`는 영화에서 null이다.
- 같은 콘텐츠와 시즌에 대한 복수 기록을 허용하므로 유니크 제약을 두지 않는다.

### 9.2 reviews

```text
id
watch_record_id
rater_key
rating
short_comment
submitted_at
edit_count
edited_at
created_at
updated_at
```

- `watch_record_id`는 `watch_records.id`를 참조하며 `ON DELETE CASCADE`다.
- `rater_key`는 현재 `me` 고정이다. 2인 도입 시 `a`와 `b`로 확장한다.
- `rating`은 1부터 5까지의 정수다.
- `short_comment`는 최대 200자다.
- `edit_count`는 표시용 누적 카운터이며 기본값은 0이다.

```text
UNIQUE(watch_record_id, rater_key)
```

### 9.3 테이블을 분리해 두는 이유

평가자가 1인이므로 두 테이블을 하나로 합칠 수 있다.
그러나 합치면 이후 2인 평가를 도입할 때 테이블을 쪼개는 마이그레이션이 필요하다.
지금 분리해 두면 추가 비용이 거의 없고 승격 경로가 열린다.

### 9.4 2인 블라인드 승격 경로

이후 참고 PRD 7.8을 도입할 때 필요한 변경은 다음이 전부다.

1. `reviews.rater_key`를 `me`에서 `a`로 백필하고 `b` 행 생성을 허용한다.
2. `watch_records.owner_key`의 의미를 그룹 식별자로 승격한다.
3. 조회 응답에서 미제출 상태의 상대 평가를 제외하고 평균과 차이를 계산한다.
4. `watch_mode = 'together'` 기록을 2인 평가 대상으로 전환한다.

테이블 추가나 컬럼 삭제 없이 가능하다.

## 10. 기술 요구사항

### 10.1 API

| 메서드 | 경로 | 역할 |
| --- | --- | --- |
| POST | `/api/records` | 기록 생성. 별점이 있으면 평가도 함께 생성 |
| GET | `/api/records` | 콘텐츠 단위로 묶은 목록. `sort`, `format`, `status` 쿼리 지원 |
| GET | `/api/records/[id]` | 기록 상세 |
| PATCH | `/api/records/[id]` | 상태, 날짜, 시즌, 메모 수정 |
| DELETE | `/api/records/[id]` | 기록과 평가 삭제 |
| PUT | `/api/records/[id]/review` | 평가 생성 또는 수정 |

### 10.2 서버 검증

모든 검증은 Route Handler에서 수행한다. 클라이언트 검증은 보조 수단이다.

- 별점이 1~5 정수가 아니면 거부한다.
- 한 줄 감상이 200자를 초과하면 거부한다.
- 메모가 500자를 초과하면 거부한다.
- 시청 상태가 정의된 3종이 아니면 거부한다.
- 날짜 형식이 `YYYY-MM-DD`가 아니면 거부한다.
- `보는 중`에 시작일이 없으면 거부한다.
- `다 봤어요`와 `중단했어요`에 종료일이 없으면 거부한다.
- 종료일이 시작일보다 빠르면 거부한다.
- KST 기준 오늘보다 나중인 날짜는 거부한다.
- 영화 기록에 `seasonNumber`가 들어오면 거부한다.
- 시즌 번호가 0 미만이거나 정수가 아니면 거부한다.
- 다른 `owner_key`의 기록에 대한 조회, 수정, 삭제 요청은 404로 응답한다.

### 10.3 소유자 식별과 보안 한계

- 첫 쓰기 요청 시 서버가 `gb_owner` 쿠키를 발급한다. UUID 값이며 `HttpOnly`, `SameSite=Lax`, 유효기간 1년이다.
- 모든 조회와 변경은 쿠키의 소유자 키로 범위를 제한한다.

**한계를 명시한다.** 이 방식은 인증이 아니라 기기 단위 구분이다.
참고 PRD 11.3의 RLS가 제공하던 보장을 대체하지 못한다.
쿠키를 잃으면 기록에 접근할 수 없고, 쿠키 값을 아는 주체는 누구든 접근할 수 있다.
개인용 프로토타입 범위에서만 성립하며, 실사용자를 받기 전에 로그인 도입이 선행되어야 한다.

### 10.4 시간대

Cloudflare Workers 런타임은 UTC로 동작한다.
"오늘"과 오전 4시 규칙은 서버에서 UTC+9로 변환해 계산한다.
날짜 계산은 단일 유틸에 모으고 단위 테스트로 보호한다.

### 10.5 성능

- 목록 조회는 콘텐츠 단위 묶음까지 서버에서 처리해 응답한다.
- 기록이 100건을 넘어도 목록 스크롤이 끊기지 않아야 한다.

### 10.6 접근성

- 별점 입력은 키보드로 조작할 수 있어야 한다.
- 선택 상태를 색상만으로 표현하지 않는다.
- 별점 버튼과 액션 버튼에 기능을 알 수 있는 레이블을 제공한다.
- 미평가와 재시청 상태를 텍스트로 안내한다.

## 11. 예외 및 오류 처리

### 11.1 저장

- D1 바인딩이 없으면 저장 기능이 비활성 상태임을 안내하고 추천 흐름은 그대로 사용할 수 있게 한다.
- 테이블이 없으면 마이그레이션이 적용되지 않았음을 안내한다.
- 저장 실패 시 입력값을 유지한 채 재시도할 수 있게 한다.

### 11.2 기록

- 같은 콘텐츠의 기존 기록이 있으면 저장 전에 재시청 기록이 추가된다는 사실을 안내한다.
- 영화에 시즌 정보가 들어오면 서버에서 거부한다.
- 상태를 변경할 때 새 상태에 필요한 날짜가 비어 있으면 입력을 요청한다.

### 11.3 평가

- 별점이 1~5 범위를 벗어나면 저장하지 않는다.
- 한 줄 감상이 200자를 초과하면 저장하지 않는다.
- 수정 내용이 기존 값과 같으면 수정 이력을 남기지 않는다.

### 11.4 삭제

- 기록을 삭제하면 연결된 평가도 함께 삭제한다.
- 삭제 전 영향을 안내한다.
- 삭제된 기록은 복구하지 않는다.

## 13. MVP 완료 조건

다음 흐름이 모바일과 데스크톱에서 모두 정상 동작하면 1단계가 완료된 것으로 본다.

### 13.1 기록과 평가

1. 추천 흐름을 진행해 결과를 받는다.
2. `이걸 볼게요`를 누르고 `다 봤어요, 기록하기`로 평가 시트를 연다.
3. 별점과 한 줄 감상을 저장한다.
4. 새로고침해도 기록이 남아 있다.
5. `이미 봤어요`에서도 평가를 남길 수 있다.
6. 별점 없이 기록만 저장할 수 있고, 미평가 안내에 표시된다.

### 13.2 수정과 되돌리기

7. 별점을 수정하면 `수정됨`이 표시된다.
8. 한 번 더 수정하면 `2회 수정됨`으로 바뀐다.
9. 같은 값으로 저장하면 수정 횟수가 늘지 않는다.
10. 상태를 `다 봤어요`에서 `보는 중`으로 되돌려도 평가가 보존된다.
11. 다시 `다 봤어요`로 바꾸면 평가가 그대로 표시된다.

### 13.3 목록

12. 함께 본 목록에서 최근 시청순과 별점 높은 순 정렬이 동작한다.
13. 콘텐츠 형식 필터와 시청 상태 필터가 동작한다.
14. 같은 콘텐츠를 다시 기록하면 카드 하나로 묶이고 재시청 배지가 표시된다.
15. 대표 별점이 가장 최근 기록의 값으로 표시된다.

### 13.4 삭제

16. 기록 삭제 시 평가도 함께 삭제된다는 안내가 표시된다.
17. 삭제 후 목록과 미평가 안내에서 해당 기록이 사라진다.

### 13.5 서버 검증

18. 별점 0과 6, 201자 감상, 영화에 시즌 번호, 미래 날짜, 시작일보다 빠른 종료일이 서버에서 거부된다.
19. 다른 소유자 키의 기록에 접근하면 404로 응답한다.
